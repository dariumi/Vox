# Changelog

## 0.17.0

Этап C, вторая модель: **Chatterbox** (Resemble AI, английский).

- **Семейство `chatterbox`**, всё на CPU и без PyTorch:
  - T3 — Llama 0.5B (30 слоёв, RoPE llama3) по речевым токенам S3: условие из эмбеддинга диктора, perceiver по речевой подсказке и вектора
    «exaggeration»; classifier-free guidance (оба прохода одним пакетом — веса читаются один раз), штраф за повторы, температура, min-p, top-p;
  - S3Gen — flow и HiFT из CosyVoice2 (тот же код) с отличиями Chatterbox: шум на каждую фразу, шаг Эйлера `t[i+1] − t[i]`, первый SineGen,
    плавное нарастание первых 40 мс;
  - VoiceEncoder (LSTM 3 × 256 по 40-полосному mel, обрезка тишины как в `librosa.effects.trim`).
- **Клонирование без текста записи**, как `prepare_conditionals`: подсказка S3Gen (mel 24 кГц, речевые токены, CAM++), эмбеддинг диктора и
  6-секундная подсказка T3. Встроенный голос из `conds.pt` — диктор `default`.
- **Эмоции → настройки модели**: новый ключ манифеста `emotion_options` — тег эмоции подставляет опции генерации (`[happy]` → exaggeration 0.8,
  cfg_weight 0.3). Работает в профилях и в разметке так же, как `instruct_emotions` у CosyVoice2.
- **`tokenizer.json`** Hugging Face читается нативно (`src/hf_tokenizer.cpp`): добавленные токены, нормализаторы Replace / Lowercase / Strip,
  претокенизаторы Whitespace / WhitespaceSplit, BPE; всё остальное отклоняется при загрузке, а не угадывается.
- **Конвертер** `python -m vox.build_chatterbox --model DIR` (или `python -m vox build`): T3 в bf16 (`--quant q8` — 8 бит), S3Gen в f32,
  размеры S3Gen — из весов. `python -m vox build` теперь передаёт `--quant q8` и конвертеру CosyVoice2.
- **Водяного знака нет**: официальный код помечает звук Perth, vox — нет.
- Исправления:
  - **CosyVoice2**: банк mel-фильтров для подсказки flow строился до 12 кГц, а в `cosyvoice2.yaml` (`feat_extractor`) — `fmax: 8000`.
    Крошечная тестовая модель повторяла ту же ошибку и поэтому её не ловила. Теперь `fmax` читается из yaml.
    **`.tmod` CosyVoice2, собранные 0.16.0, нужно пересобрать.**
  - Python и CLI: JSON из C ABI (`devices`, `inspect`, `plan`, `session_info`, `stats`, `phonemize`) мог обрезаться, если текст вырастал между
    запросом размера и самим вызовом (так падал `test_library` на `devices()` — свободная память меняется). Теперь при нехватке места запрос повторяется.
  - Движок: модель в режиме «direct», выдавшая кусок без звука после конца текста, больше не останавливает сессию ошибкой.
  - Пример на Node.js иногда портил звук: запись в канал асинхронная, а буфер перезаписывался следующим `pull`. Теперь пишется копия.
- `tools/make_tiny_chatterbox.py` (крошечная модель из официальных классов, эталоны всех стадий и четырёх целых фраз; `--full` — настоящие размеры
  для замеров), `tests/test_chatterbox_tiny.py`, шаг в CI.

Проверено (крошечная модель, `chatterbox-tts` 0.1.7): каждая стадия в f32, bf16 и q8; целые фразы через движок совпадают с `ChatterboxTTS.generate`
до 1.3e-5 при четырёх наборах опций; подсказка S3Gen клонированного голоса совпадает полностью, VoiceEncoder — с косинусом 0.999997; текст — как у
`EnTokenizer` на 8 строках. Скорость на настоящих размерах (случайные веса, 2 ядра): T3 ~250 мс на токен (bf16) / ~150 мс (q8), RTF ≈ 15–17.
Не проверено: настоящие веса ResembleAI/chatterbox и их `tokenizer.json` (нет доступа к Hugging Face при разработке); качество звука; GPU.
Расходится с официальным кодом намеренно: подсказка T3 у клона считается по 16 кГц от ресэмплера torchaudio (у них soxr) — на крошечной модели
57% токенов подсказки совпадают; длинный текст режется на группы предложений по 300 символов; `cfg_weight` 0 разрешён.

## 0.16.0

Этап C задачи «профили, эмоции, Studio, модели»: новая модель **CosyVoice2-0.5B** (FunAudioLLM).

- **Семейство `cosyvoice`**, всё на CPU и без PyTorch:
  - Qwen2 LM 0.5B по речевым токенам (25 Гц, 6561 код FSQ) с официальным сэмплингом RAS (top-p 0.8, top-k 25, окно 10 против повторов,
    конец речи не раньше 2 токенов на токен текста) на Philox;
  - flow: эмбеддинг токенов, Conformer-энкодер с относительными позициями и повышением частоты ×2, conditional flow matching
    (U-Net с трансформерными блоками, 10 шагов Эйлера по косинусной сетке, CFG 0.7, фиксированный шум оригинала);
  - вокодер HiFT: предиктор F0, гармонический источник NSF, транспонированные свёртки с Snake, iSTFT.
- **Клонирование голоса нативно**, как в `CosyVoiceFrontEnd`: mel 24 кГц, Kaldi fbank → CAM++ x-vector, log-mel Whisper → речевые токены
  S3TokenizerV2, выравнивание токенов и mel. Передискретизация записи — алгоритм torchaudio (`Resample`), поэтому токены те же,
  что у официального кода. С текстом записи — режим zero-shot, без него — cross-lingual.
- **Инструкции и эмоции** (`instruct2`): стиль профиля с `--instruct` или тег эмоции (`[happy]`, `[радостно]`). Если в манифесте модели есть
  `instruct_emotions`, движок берёт формулировку оттуда (для CosyVoice2 — китайские фразы, на которых её учили), иначе английскую по умолчанию.
  Инструкции теперь работают и с клонированными голосами, если модель это умеет (раньше только с дикторами).
- **Теги**: `[laugh]` → собственный токен модели `[laughter]`, `[breath]`, `[cough]`, `[sigh]`.
- **Текстовый фронтенд** — `text_normalize` без ttsfrd / wetext: китайские правила, числа словами по правилам inflect, группы
  предложений по 60–80 токенов. Стриминг текста отдаёт группу, как только она больше не может измениться: звук при подаче по кускам
  совпадает с синтезом всего текста. `vox phonemize` для CosyVoice показывает куски и их токены.
- **Конвертер** `python -m vox.build_cosyvoice --model CosyVoice2-0.5B/` (или `python -m vox build`): LLM в bf16 (по умолчанию), flow и HiFT в f32,
  weight norm сворачивается, CAM++ читается из `campplus.onnx` по узлам графа и сверяется с onnxruntime при конвертации,
  токенизатор речи — через `s3tokenizer.utils.onnx2torch`. `--quant q8` — линейные слои LLM в 8 битах (на токен 59 мс вместо 96 на 2 ядрах).
- **Скорость** (настоящие размеры, случайные веса, 2 ядра): LLM 96 мс на речевой токен (bf16), 59 мс (q8); flow — основная нагрузка
  (56 трансформерных блоков × 10 шагов × 2 прохода CFG): 16 с на 2,4 с речи; итого RTF ≈ 7–10. Проходы с подсказкой и без неё считаются
  одним пакетом, GELU, softmax и exp — векторно (AVX2). На GPU модель пока не запускается.
- **Общие слои** вынесены из Kokoro в `src/nn.cpp`: свёртки, источник NSF, STFT / iSTFT, внимание через matmul, DFT любой длины,
  ресэмплер torchaudio. Kokoro после переноса проходит свои тесты без изменений.
- `vox_session_info` отдаёт поле `model` — что модель сделала в сессии (у CosyVoice: режим и куски текста).
- `tools/make_tiny_cosyvoice.py` (крошечная модель из официальных классов и эталоны всех стадий; `--full` — настоящие размеры со случайными
  весами для замеров), `tools/cosyvoice_ref.py`, `tests/test_cosyvoice_tiny.py`.

Проверено (крошечная модель, официальный код CosyVoice, onnxruntime, s3tokenizer): каждая стадия в f32 и bf16 в трёх режимах;
целые фразы через движок совпадают с `CosyVoice2Model.token2wav` до 1.4e-5; куски текста совпадают с `text_normalize`.
Не проверено: настоящие веса CosyVoice2-0.5B (нет доступа к Hugging Face при разработке), качество инструкций на английском и китайском.

## 0.15.0

Этапы A и B большой задачи «профили, эмоции, Studio, модели»: многоголосые профили для любых моделей, разметка интонации в тексте и
Vox Studio — управление движком из браузера.

- **Профиль голоса** — тот же `.tvoice`, но с несколькими голосами. У голоса:
  - стили (эмоции, подача): у каждого своя запись-образец и/или инструкция и параметры (`speed`, сэмплинг);
  - записи с текстом, по которым голос собирается на любой модели с клонированием;
  - готовые дикторы для моделей без клонирования (`speakers`: `kokoro`, `qwen3-tts/custom_voice`);
  - описание для VoiceDesign и параметры голоса;
  - кэш голосов, уже собранных под конкретные модели (по sha256 весов).
- **Один профиль на всех моделях.** Если голоса под модель в кэше нет, он собирается при первом использовании и сохраняется
  `save()` / `vox profile prepare`:
  - Qwen3 Base и F5 собирают его из записи. Голос, созданный на одной модели, работает на другой: проверено на F5, результат бит в бит
    совпадает с клонированием той же записи прямо на F5;
  - Kokoro и Qwen CustomVoice берут указанного для них диктора;
  - VoiceDesign берёт описание голоса плюс инструкцию стиля.

  Если собрать нельзя, ошибка говорит, что добавить (например, `--speaker kokoro=NAME`).
- **Разметка в тексте** (`markup`: `auto` по умолчанию, `strict`, `off`). Где модель не умеет то, что просят, движок переводит подсказку
  сам, и модель никогда не читает её вслух; что не удалось, записано в `notes` сессии.
  - Голос: `[voice:anna]`, `[anna]`, реплики `anna: …` в начале строки.
  - Стили и эмоции: `[happy]`, `[радостно]`. Эмоция без своего стиля в профиле становится инструкцией у Qwen CustomVoice 1.7B и
    VoiceDesign или темпом у F5 и Kokoro.
  - `[/]` возвращает стиль по умолчанию.
  - Пауза точной длины: `[pause 500ms]`, `[пауза 300мс]`.
  - Темп: `[speed 1.2]`.
  - Невербальные звуки `[laugh]`, `[sigh]`: собственный тег модели, если он есть, иначе короткая пауза.

  Ключевые слова есть по-английски и по-русски. Текст вокруг тегов звучит так, как если бы каждый кусок сказали отдельно. Тег может прийти
  разрезанным между порциями дуплекс-стриминга. Каждый переход — отдельный сегмент с собственным состоянием модели.
- **Совместимость в обе стороны**:
  - `.tvoice` 1.0 открывается как профиль из одного голоса и звучит бит в бит как раньше;
  - профиль, у голоса по умолчанию которого есть сборка, пишется в формате 1.1: на верхнем уровне в нём этот голос в раскладке 1.0, и
    vox 0.14.1 читает такой файл как обычный голос (проверено: звук тот же), vox.js тоже;
  - профиль без сборок — формат 2.0, старые версии от него отказываются.
- **ABI 0.5**: `vox_profile_new`, `vox_profile_open` (без модели), `vox_voice_add_recording`, `vox_voice_merge`, `vox_voice_update`
  (JSON merge patch описания), `vox_voice_prepare`. `vox_voice_info` отдаёт профиль и, для старых клиентов, поля голоса по умолчанию.
  В `extra_json` сессии: `voice`, `style`, `markup`. В `Capabilities` добавлены `speed` и `tags`.
- **CLI**:
  - `vox profile new|add|set|rm|patch|show|prepare`;
  - у `vox say`, `vox live` и `vox bench` новые флаги `--voice-id`, `--style`, `--markup`;
  - `vox info file.tvoice` показывает профиль.
- **Python**:
  - `vox.Profile(name)`, `Voice.open(path)`;
  - методы `add_recording`, `add` (слияние), `set_voice`, `set_style`, `remove`, `update`, `prepare`, свойства `voices`, `default_voice`;
  - параметры синтеза `voice_id=`, `style=`, `markup=`;
  - фронтенд misaki для Kokoro пропускает разметку не фонемизируя.
- **Сервер**: в `GET /v1/voices` профили с несколькими голосами дают ещё `файл:голос`; в `/v1/tts` и WebSocket можно указать `"voice": "cast:anna"`,
  `voice_id`, `style`, `markup`.
- **WAV PCM16** пишется как round(x·32768) — точное обращение чтения (x/32768). Раньше было ×32767 с отсечением, и запись, прочитанная и записанная
  снова, менялась.
- Тесты: `tests/test_profiles.py`:
  - совместимость 1.0 / 1.1 / 2.0 и CLI;
  - разметка: пауза точной длины, детерминизм, режимы auto/strict/off, теги, разрезанные между вызовами `feed()`;
  - сборка на F5 и Kokoro, Python API.

  Профиль через HTTP проверяется в `test_api_serve.py`.

- **Vox Studio** (этап B): `vox web` или `vox -web` (`python/vox/web.py`) поднимает движок со встроенным сервером и печатает ссылки с секретом —
  на страницу `vox.arkonova.network/studio/` и на копию Studio, которую раздаёт сам движок.
  - **Studio** (`site/studio/index.html`, одна страница без зависимостей, русский и английский):
    - сценарий с несколькими голосами, чипами разметки и подсветкой тегов;
    - звук играет, пока синтезируется, с волной и загрузкой;
    - заметки движка, RTF и время до первого звука;
    - профили: запись с микрофона или из файла (конвертируется в WAV в браузере), стили, инструкции, темп, готовые дикторы для моделей,
      «собрать под модель», скачать и загрузить .tvoice;
    - модели: открыть, закрыть, устройство, добавить по пути;
    - история.
  - **API**: модели, профили (создать, PATCH, записи, prepare, скачать и загрузить), `POST /v1/speak` (потоком pcm16 / f32 / wav, клип
    в историю с заметками), `/v1/history`, WebSocket `/v1/duplex`.
  - **Безопасность и доступ.** Секрет обязателен для всего под `/v1` (заголовок или `?token=`); в ссылке он после `#`, поэтому сайту со
    страницей не уходит. CORS и `Access-Control-Allow-Private-Network` разрешают странице с другого сайта ходить к локальному движку.
  - **HTTPS.** `--tls` создаёт самоподписанный сертификат на имена и адреса машины (через `cryptography` или `openssl`), можно и свой
    `--cert/--key`. Это доступ по сети с https-страницы — тот же путь, что `external-controller-tls` у Clash.
  - На странице проекта — кнопка «Vox Studio».
  - Тест `tests/test_web_studio.py`:
    - секрет, CORS, модели и профили;
    - `/v1/speak` = библиотека бит в бит, история, WebSocket, TLS;
    - страница Studio в Chromium: подключение, озвучка с разметкой, вкладки, подсказка при недоступном движке.

**Не проверено:** разметка и эмоции на настоящих весах (на случайных весах проверены только механика и точность): насколько естественно
звучат стыки сегментов, как Qwen 1.7B выполняет инструкции эмоций. vox.js профили не собирает и разметку не понимает: он читает голос по умолчанию.
Studio: проверена в Chromium (headless) против движка на этой же машине. Не проверены Safari и Firefox, телефон на реальном устройстве,
доступ по сети с другого компьютера (`--tls`), запрос разрешения Chrome на локальную сеть и реальное время синтеза на настоящих моделях.

## 0.14.1

По отчёту о тестах 0.14.0 (RTX 5050 + RTX 3050, настоящие веса Qwen3-TTS 1.7B, F5 hotstone, Kokoro-82M).

- **Умножение матриц на CPU при многих строках входа** (префилл, DiT, Vocos, свёртки Kokoro) стало быстрее. Звук совпадает бит в бит, потому что
  у каждого выхода прежний порядок суммирования; сверено на F5 f32/bf16/q8 и Kokoro, 1 и 2 потока.
  - Работа делится не только по строкам весов, но и по строкам входа: задача — 64 строки входа × до 256 строк весов. Раньше каждый поток заново читал
    весь вход, и при малом числе строк весов на поток (свёртки генератора Kokoro: 128–256 каналов, 16 потоков — по 8–16 строк) упирался в память.
    Поэтому Kokoro на 16 потоках был медленнее torch. `VOX_MM2D=0` возвращает старое деление.
  - Плитка при m > 1: 4 строки весов × 3 строки входа (12 аккумуляторов, все 16 регистров ymm) вместо 2 × 4.
  - Замер на 2-ядерной машине разработки:
    - Kokoro (тестовая модель с настоящей шириной декодера и генератора): RTF 0,89 → 0,56 на 2 потоках, 1,29 → 1,02 на одном;
      свёртки генератора на 2 потоках масштабируются в 2,0 раза вместо 1,47;
    - F5 (DiT с настоящей шириной слоёв, 2 слоя), RTF: f32 0,52 → 0,35, bf16 0,52 → 0,42, q8 0,51 → 0,39.
  - На 16 потоках выигрыш от деления по входу должен быть больше; замерить на вашей машине.
- **F5: Vocos по умолчанию в f32** (`python -m vox.build_f5 --vocos-dtype f32|f16|bf16`, в vox.js — `vocosDtype`; ключ кэша
  конвертаций в браузере сменился, так что модели перестроятся). Раньше `--dtype bf16` касался и матриц вокодера.
  - Вокодер маленький (+26 МБ к модели), но мел в нём превращается в фазу, поэтому его ошибка видна в относительной L2 волны.
  - На модели с настоящей шириной Vocos ошибка волны против `f5_tts`: bf16 1,97e-3 → 1,41e-3, q8 2,0e-3 → 1,47e-3.
  - На настоящих весах в отчёте мел bf16 3,8e-3, а волна 8,8e-2. Сколько из этого уберёт f32-Vocos, покажет `check_f5_real.py` после пересборки модели.
- **F5 на GPU** (скорость ещё не измерена: в окружении разработки только lavapipe; сквозной звук на нём совпадает с CPU до 4e-9):
  - Новый шейдер `gemmb.comp` для линейных слоёв DiT и Vocos (f32/f16/bf16/q8): плитка 128×128 на группу, 8×8 выходов на поток, 64 FMA на 4 чтения
    vec4 из shared-памяти. Старый `convgemm` делал 16 FMA на 8 скалярных чтений и целочисленное деление на каждый загруженный элемент.
    `VOX_F5_GEMM=old` возвращает старый путь. В профиле GPU шейдер называется `gemm8x8.*`.
  - Внимание (`f5attn.comp`): K и V в shared-памяти лежат строками vec4. Оценка — 16 `dot()` по vec4 вместо 64 скалярных чтений, P·V — 2 чтения vec4 на 8 FMA.

## 0.12.2

F5-TTS на `hotstone228/F5-TTS-Russian` наконец совпадает с официальным: обе причины нашла тестировщица (отчёт по 0.12.1), здесь они исправлены и закрыты тестами.

- **Словарь с CRLF.** `vocab.txt` у части дообучений записан с `\r\n`; конвертер делил только по `\n`, и каждый токен получал хвост `\r` — ни один символ текста

- **Обрезка краёв iSTFT у Vocos.** У `charactr/vocos-mel-24khz` голова `padding: center` (как `torch.istft(center=True)`: срез `n_fft/2`, длина `(T−1)·hop`),
  а vox всегда резал как для `same` (`(n_fft−hop)/2`) — звук был сдвинут на 128 отсчётов и длиннее на 256. Теперь `padding` читается из `config.yaml` вокодера
  в манифест (`f5.vocos.padding`); нет конфига — считается `center` (это официальный вокодер F5-TTS). В браузере `config.yaml` скачивается рядом с весами
  (или `opts.vocosConfig` / `opts.vocosPadding`). Старые `.tmod` без поля читаются как `same` (как раньше), поэтому **модели с настоящим Vocos нужно сконвертировать заново**;
  ключ кэша конвертации в браузере сменился (`tmod/2`), старые кэшированные модели пересоберутся сами.
- Тесты: крошечная v0-модель теперь собирается со словарём CRLF и Vocos `center` (`make_tiny_f5.py --crlf-vocab --vocos-center`) и сверяется с `f5_tts` + `vocos`:
  стадии и сквозной звук в ядре, браузер (WebGPU и CPU) = ядро; разбор `config.yaml` и словаря — в `web_convert_check.js`.
  Проверено, что старое поведение на этой модели падает: токены `rel 1.0`, длина звука 9472 против 9216.
- `tools/check_f5_real.py`: печатает ошибку mel против официального (до вокодера), сдвиг звука по взаимной корреляции и ошибку после выравнивания, ругается на сплошные нулевые токены.
- `tests/test_api_serve.py`: сервер на свободном порту и гасится при падении (`atexit`). Случайное «server f32 stream differs», вероятно, было отсюда:
  на занятом 18080 запросы уходили к серверу, оставшемуся от прошлого прогона. `tests/test_official.py`: Python-API открывает явно заданное устройство (`VOX_TEST_DEVICES`), а не `auto`.
- `tests/test_api_serve.py`: библиотека и `vox serve --device` открывают одно и то же устройство из `VOX_TEST_DEVICES` (с `auto` они брали разные видеокарты,

- **Слитые веса слоя:** q|k|v и gate|up загружаются одной матрицей (без копий в VRAM). На слой 4 matmul вместо 7,
  разбор QKV по KV-кэшу и SwiGLU — отдельные шейдеры.
- **Цикл code predictor целиком на GPU:** 15 проходов, сэмплинг в шейдере (bitonic top-k, top-p, Philox (frame, cb)),
  выборка эмбеддинга по индексу из буфера — одна отправка на кадр. Синхронизаций с хостом на кадр было 16, стало 2.
  С CPU-сэмплингом совпадает побитово на тестовом прогоне (60 кадров, T=0.9). `VOX_GPU_SAMPLING=0` выключает.
- `run_full_check.py`: абсолютные пути (относительный `--out` работал не из любой папки); внешний движок через
  `sh -c` и до `--bench-runs` запусков; `--external-time` (RTF синтеза по выводу движка, отдельно от RTF всего
  процесса); `--asr-cmd` (whisper.cpp и др.); WER и CER для каждой пары «формат × устройство» с числами, приведёнными
  к словам; пик памяти внешнего движка считается по его процессу.

Замер 0.6 у пользователя (Ryzen 7 5700X, RTX 3050, ~13 с речи, тёплый запуск): Vulkan bf16 RTF 0.88 (talker 23,
predictor 32, декодер 5 мс/кадр), Vulkan q8 1.20, CPU q8 1.78, CPU bf16 2.85; qwentts.cpp CUDA 0.43, CPU 2.06–2.12.
Сверка на 1.7B-Base: 30/30 PASS (bf16 отн. ошибка ≤ 8e-6; q8 KL ≤ 5e-3). Ошибка 5.756e-2 исчезла. Голос: эмбеддинг
1.15e-7, коды 100%.

Найдено и исправлено
- **Ошибка аудио 5.756e-2 (отчёт по 0.4).** Причина — нарезка декодера в `qwen_tts` (`chunked_decode`: куски по 300
  кадров, 25 кадров контекста), а не bf16, как предполагалось в 0.5. Добавлен режим `--decoder reference`
  (`VOX_DECODER_REFERENCE` в C ABI, `decoder_mode` в Python), побитово повторяющий эту схему. `vox verify`
  использует его всегда.
- `vox verify`: при упоре в `max_new_tokens` оригинал отдаёт на кадр меньше. Свободная генерация теперь
  сравнивается по числу кадров эталона.
- В режиме `codec=cpu` веса трансформера декодера больше не загружаются в VRAM. Раньше каждая их матрица считалась
  отдельной отправкой на GPU с ожиданием.

Новое
- **Нативное создание голоса**: мел-спектр (slaney, STFT), ECAPA-TDNN, энкодер Mimi (SEANet, трансформер,
  понижение частоты, split RVQ), ресемплер sinc/Kaiser. `vox voice create`, `Engine.clone_voice` и
  `POST /v1/voices` работают без torch. С официальным кодом: эмбеддинг ≤ 4e-7, коды 100%.
- **Декодер кодека целиком на GPU**: свёрточный implicit-GEMM (тайлы 64×64, f32/f16/bf16 веса), Snake,
  depthwise-свёртка, LayerNorm, overlap-add транспонированных свёрток, внимание со скользящим окном на кольцевом KV,
  потоковые истории в видеопамяти. Один командный буфер на чанк, режим по умолчанию для Vulkan.
- talker и predictor: входная проекция, трансформер, норма и голова — одна отправка на проход
  (было три у predictor и две у talker).
- `VOX_PROFILE=gpu`: метки времени GPU по каждому шейдеру, сводка «стадия/шейдер».
- q8 квантует и головы/проекции (`codec_head`, `lm_head.*`, `small_to_mtp_projection`, `text_projection`).
- `VOX_CODEC_DEBUG_STAGE=k`: активация после стадии k декодера (сравнение CPU и GPU по шагам).
- `run_full_check.py`: нативный голос со сравнением против `qwen_tts`, GPU-профиль и размещение весов в отчёте,
